# 外国語PDF 日本語オーバーレイ翻訳

外国語（ベトナム語・英語・ミャンマー語）のPDF（複数ページ対応）をアップロードすると、常駐しているローカルLLM（[llama.cpp](https://github.com/ggml-org/llama.cpp) + gemma-4-12b）が日本語に翻訳し、元のレイアウトの上に日本語訳を重ねて表示するデモアプリです。翻訳はすべてローカルで完結し、外部のクラウドAPIへPDF本文が送信されることはありません。

## 特徴

- **複数ページ対応**: 全ページを縦スクロールで連続表示し、1ページ目から順にテキスト抽出/OCR・翻訳を自動処理します。画面に近いページだけを実際に描画し、離れたページは解放するため、ページ数が多いPDFでもメモリを圧迫しません。処理はいつでも中断・再開でき、ページ番号を指定してジャンプもできます。
- **オーバーレイ表示**: PDFを`pdfjs-dist`でcanvasに描画し、抽出したテキストの座標に合わせて日本語訳を重ねて表示します。原文の位置関係やレイアウトを保ったまま読めます。JBIG2/JPEG2000圧縮のスキャンPDFにも対応しています。
- **原文言語の自動判定 / 手動選択**: 抽出したテキストの文字種比率（ミャンマー文字・ベトナム語声調記号・ラテン文字）から原文の言語を自動判定します。判定結果は画面上の「原文の言語」から手動でも切り替えられます（自動 / ベトナム語 / 英語 / ミャンマー語）。
- **テキスト層 / OCR 自動判定**: PDFにテキスト層があればそのまま抽出し、スキャン画像などテキスト層を持たないPDFは自動的に[tesseract.js](https://github.com/naptha/tesseract.js)によるOCRにフォールバックします。原文言語が未確定の間は候補言語（ベトナム語・英語・ミャンマー語）を同時に読んで言語を判定し、確定後は「該当語＋英語」で読み直して精度を上げます。言語データ（traineddata）はビルド時に`public/`へ同梱するため、オフライン環境でも動作します。
- **回転スキャンページの自動補正**: スキャン画像の中身自体が90°単位で回転しているページ（複合機でページの向きを揃えずにスキャンした場合等）を検出し、正立させてからOCR・翻訳します。0/90/180/270°で低解像度OCRを試し、最もよく読める向きを採用する方式で、追加の言語データやコンポーネントは必要ありません。補正したページには「向きを補正」のバッジが表示されます。
- **OCRエリアの手動指定**: 自動OCRから漏れた項目は、PDF表示上でマウスドラッグして範囲を追加指定できます。指定した範囲だけを高解像度でOCR・翻訳し、オーバーレイに追加します。
- **再翻訳・翻訳結果の削除**: 翻訳済みのボックスにマウスをホバーすると「再翻訳」「削除」ボタンが表示されます。文字化けなど訳が不適切な場合はその場で送り直せるほか、削除してOCRエリア指定で範囲を囲み直すことでも再翻訳できます。
- **文脈適応翻訳（2パス翻訳）**: 単語・セル単位の独立翻訳（パス1）だけでは文書全体の文脈が失われ精度が落ちがちな問題に対応します。「文脈を踏まえて全体を再翻訳」を実行すると、パス1の訳文一式をLLMに見渡させて文書の分野（金融・法務・医療・技術など）を推定し（パス2）、その文脈を全行の再翻訳プロンプトに埋め込みます。パス2で見直された訳文は、パス1時点の訳文と文字単位で比較し、実際に変わった部分だけが赤字で表示されます。MoE（Mixture of Experts）モデルを使う場合、分野ヒントがプロンプト先頭にあることで該当分野に強い専門家が選ばれやすくなる効果も期待できます。
- **表形式に対応**: 単語・テキスト断片の水平方向の隙間からセル境界を推定し、表の列同士が混ざらないようセル単位で翻訳します。
- **ローカルLLM連携**: OpenAI互換API（`/v1/chat/completions`）でllama.cppサーバーに1行ずつ翻訳をリクエストします。タイムアウト・リトライを行い、翻訳に失敗した行は原文表示にフォールバックします。
- **既存の日本語訳を保護**: 対訳PDFなど、原文の隣にすでに日本語訳が印字されている場合は二重翻訳せず、そのまま参照として残します。
- **表示調整**: 原文⇄訳のトグル切り替え、拡大縮小（50%〜300%）、ドラッグ＆ドロップでのPDF読み込みに対応しています。
- **PDFとして保存**: 「PDFとして保存」ボタンを押すと、アプリのヘッダー・ツールバーを除いた翻訳結果（元PDFページ＋日本語オーバーレイ）だけを対象にブラウザの印刷ダイアログを開きます。「送信先」を「PDFに保存」にすれば、翻訳結果だけのPDFファイルが得られます。画面外で未描画（メモリ節約のため解放済み）のページも自動的に強制描画してから印刷するため、スクロールしていないページも欠けずに出力されます。

## セットアップ

### 前提: ローカルLLMサーバー

このPCに常駐する llama.cpp サーバー（OpenAI互換API）が必要です。既定では以下を想定しています。

- エンドポイント: `http://127.0.0.1:8080`
- モデル: `gemma-4-12b-it-Q4_K_M.gguf`

エンドポイントやモデルを変更する場合は `.env.local` に以下を設定してください。

```bash
LLAMA_BASE_URL=http://127.0.0.1:8080
LLAMA_MODEL=gemma-4-12b-it-Q4_K_M.gguf
```

`LLAMA_MODEL` は Mixtral・Qwen3-MoE など MoE（Mixture of Experts）系のモデルにも差し替えられます。ただし、どの専門家ネットワークが実際に活性化されるかはモデル内部のルーティング次第で、アプリ側から専門家を直接指定するAPIはありません。「文脈適応翻訳」機能が付与する分野ヒントは、あくまでモデルが適切な専門家を選びやすくなるようプロンプトで手がかりを与えるものです。

### インストールと起動

```bash
npm install
npm run dev
```

`npm install` / `npm run dev` 時に `scripts/copy-pdfjs-assets.mjs` が自動実行され、`pdfjs-dist` のworker/フォント/wasm（JBIG2等のデコード用）と `tesseract.js` のworker/コア/言語データ（ベトナム語・英語・ミャンマー語）を `public/` に同期します。

[http://localhost:3000](http://localhost:3000) を開き、PDFをアップロードして翻訳結果を確認できます。

## 使い方

1. **PDFを読み込む**: 「PDFをアップロード」ボタンから選択するか、画面下部のエリアへドラッグ＆ドロップします。複数ページのPDFも、そのまま読み込めば1ページ目から順に自動処理されます。
2. **自動翻訳を確認する**: テキスト層またはOCRで抽出した項目が、ページごとに順にローカルLLMで翻訳されます。黄色（翻訳待ち）→ 水色（翻訳完了）/ オレンジ（翻訳失敗・原文のまま）の順で状態が変わります。画面上部に「解析 5/14ページ・翻訳 128/342件」のように進捗が表示されます。処理は「処理を中断」ボタンでいつでも止められ、「処理を再開」で処理済みページをやり直さずに続きから進められます。
3. **ページを移動する**: 「ページ移動」欄にページ番号を入力するとそのページへスクロールします。
4. **漏れを補う**: 「OCRエリア指定」を有効にし、自動抽出で拾えなかった箇所をマウスドラッグで囲むと、その範囲を追加でOCR・翻訳します。
5. **誤りを直す**: 翻訳済みのボックスにマウスを乗せると表示される「再翻訳」「削除」ボタンで、訳をやり直したり、削除してから範囲を指定し直したりできます。
6. **文脈を踏まえて仕上げる**: 一通り翻訳が終わったら「文脈を踏まえて全体を再翻訳」を押すと、文書の分野を推定したうえで全項目（全ページ横断）を訳し直します。推定結果（例:「ベトナムの銀行が発行した法人向け口座取引明細書」）は画面上に表示されます。
7. **PDFとして保存する**: 「PDFとして保存」ボタンを押すと、画面外の未描画ページも含めて全ページを準備したうえでブラウザの印刷ダイアログが開きます。「送信先」を「PDFに保存」にすると、アプリのヘッダー・ツールバーを除いた翻訳結果だけのPDFファイルが得られます。

## 技術スタック

- Next.js 16 (App Router) / React 19 / TypeScript / Tailwind CSS v4
- [pdfjs-dist](https://www.npmjs.com/package/pdfjs-dist) — PDF描画・テキスト座標抽出
- [tesseract.js](https://www.npmjs.com/package/tesseract.js) — OCR（テキスト層のないPDF・手動指定エリア向け）
- ローカルLLM（llama.cpp, OpenAI互換API）— 翻訳

## 主なディレクトリ構成

```
app/
  api/
    translate/route.ts         # ローカルLLMへの翻訳リクエスト（パス1/パス2共通、Route Handler）
    analyze-document/route.ts  # パス2: 文書全体の分野推定（Route Handler）
  components/
    PdfTranslatorApp.tsx       # 状態管理・アップロードUI・ズーム・OCRエリア指定/再翻訳/文脈適応翻訳の操作
    PdfOverlayViewer.tsx       # ドキュメント担当: 全ページのテキスト抽出/OCRを順次処理し進捗を管理
    PdfPageView.tsx            # ページ担当: 1ページぶんの遅延描画・オーバーレイ表示・手動選択レイヤー
  lib/
    pdf.ts                     # pdfjs読み込み・テキスト抽出・セル分割
    ocr.ts                     # tesseract.js によるOCRフォールバック・手動エリアOCR
    translate-client.ts        # 翻訳APIのチャンク分割・呼び出し・文書分野推定の呼び出し
    types.ts                   # 共有型定義
scripts/
  copy-pdfjs-assets.mjs        # pdfjs-dist / tesseract.js の資産・言語データを public/ に同期
```
